# SwiftUI 版 Typle Data Viewer 試作 設計

- 日付: 2026-11-06
- ブランチ: `claude/swiftui-version-595656`（`main` の AppKit 版は変更しない）

## 目的

AppKit 版と比べるための試作を SwiftUI で作る。AppKit 版を置き換えることは目的にしない。

## 完了条件

1. `swift build` が通り、アプリが起動する。
2. 「範囲」の「入れる機能」が、実際の PostgreSQL に接続して動く。
3. `docs/superpowers/specs/2026-11-06-swiftui-comparison.md` に比較メモがある。内容は次の3点。
   - コード量（UI 層の行数を AppKit 版と比較）
   - 作りにくかった点、SwiftUI では実現できなかった点
   - 1,000 行のページを表示したときの操作感（表示までの時間、スクロール、選択）

## 範囲

### 入れる機能

| 機能 | 内容 |
|---|---|
| 接続 | `DATABASE_URL` と保存済み接続先から選び、接続・切断する。状態（未接続、接続中、接続済みとサーバーのバージョン、失敗）を表示する |
| 一覧 | テーブルとビューをサイドバーに出す。種類が分かるアイコンを付ける。接続後は先頭を選ぶ |
| データタブ | 1,000 行ごとのページ送り、絞り込み（全列または1列）、見出しでの並べ替え、総件数の表示。NULL は斜体、数値の列は右寄せ |
| スキーマタブ | 列の一覧（列名、型、NOT NULL、既定値、キー）、推定行数、サイズ、インデックス |
| SQL タブ | 読み取り専用の SQL を `Cmd+Return` で実行し、結果を表で出す。行数、実行時間、打ち切りの有無を表示する。入力欄が空なら、選択中のテーブルの SELECT を入れる |
| コピー | 選択した行を TSV でコピーする（`Cmd+C`） |
| 再読み込み | `Cmd+R` で選択中のテーブルを読み直す |

### 外す機能

接続先の追加・編集・削除、外部キー移動と「戻る」、列の並び・幅・非表示の記憶、エクスポート、値ウィンドウ、起動時の状態復元、サンプルデータ、日英切替。

UI の文言は日本語のみとする。

## 構成

このブランチでは AppKit の UI を置き換える。2つのアプリを同じパッケージに同居させる案は、共通部分の切り出しが必要になるので採らない。比較は `main` との差分と、それぞれのビルドで行う。

| ファイル | 扱い | 役割 |
|---|---|---|
| `Database.swift` | 変更しない | DB アクセス |
| `Connections.swift` | 変更しない | 接続先の保存、Keychain |
| `Export.swift` | 変更しない | エクスポート機能は作らない。行のコピーで `TableExporter.tsvField` だけ使う |
| `main.swift` | 削除 | AppKit の UI と状態 |
| `ValueWindow.swift` | 削除 | 値ウィンドウ |
| `CopyableTableView.swift` | 削除 | `NSTableView` のサブクラス |
| `TypleDataViewerApp.swift` | 新規 | `@main`、ウィンドウ、メニューコマンド |
| `AppModel.swift` | 新規 | `@Observable` の状態、接続と読み込みの処理 |
| `ContentView.swift` | 新規 | ツールバー、サイドバー、タブの切り替え |
| `DataGrid.swift` | 新規 | 動的列の `Table`。データ、スキーマ、SQL の結果で共用する |
| `SQLView.swift` | 新規 | SQL 入力欄と結果の表示 |

`Package.swift` の対応 OS を `.macOS("14.4")` に上げる。`TableColumnForEach` が macOS 14.4 以降を必要とするため。

## データの流れ

- `AppModel`（`@MainActor`）が接続、一覧、選択中のテーブル、タブ、表示中の結果を持つ。ビューは状態を描き、操作を `AppModel` のメソッドに渡すだけにする。
- `DataGrid` は列名、行、数値列の位置を受け取る。行は取得時の位置を ID にする。
- 読み込みごとに世代番号を増やし、完了時に番号が古ければ結果を捨てる。読み込み中にテーブルやタブを切り替えても、結果が混ざらない。
- テーブルを切り替えたら絞り込み、並べ替え、ページを初期状態に戻す。
- 再読み込みで行が減り、いまのページが範囲外になったら最後のページを読み直す。
- データタブの並べ替えは `TableQuery` の `sortColumn` と `ascending` を変えて DB で行う。スキーマと SQL の結果は手元の行を並べ替える。

## エラー処理

- 接続の失敗はツールバーの状態表示に出す。`DATABASE_URL` の未設定、形式の誤りは専用の文言にする。
- テーブルの読み込みと SQL の失敗は `.alert` で出す。
- 接続中に接続先を変えたら、できた接続を閉じて使わない。
- 実行中に切断したら SQL の結果を捨てる。

## 既知の制約

- `.app` にしない実行ファイルは、ウィンドウを前面に出すために `NSApp.setActivationPolicy(.regular)` が必要になる見込み。これが AppKit を使う唯一の箇所になる。
- 動的列の見出しソートを `Table` の `sortOrder` で書けるかは未確認。難しければ、並べ替えの列と向きを選ぶ UI をツールバーに置き、その事実を比較メモに残す。
- 実行ファイルが変わるので、Keychain の確認が一度出ることがある。

## 確認方法

- Docker のローカル PostgreSQL にテーブル、ビュー、マテリアライズドビュー、1,000 行を超えるテーブルを用意し、「入れる機能」を順に試す。
- Docker が使えない場合は、確認できなかった範囲を比較メモと報告に明記する。
- UI 層の自動テストは書かない。試作であり、既存の AppKit 版にもテストがないため。並べ替えなど `AppModel` の純粋なロジックは、切り出せる場合のみテストする。
